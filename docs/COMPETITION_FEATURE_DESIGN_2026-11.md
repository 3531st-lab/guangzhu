## 三项实施设计与验收

### P0：三维直接操作与工程复算联动

用户在三维中选组件后直接拖动或旋转；吸附控制位置和角度。拖动过程中只显示候选，松手后走现有后端预览；用户核对影响后保存新版本。

验收条件：

1. 平屋面保持支架倾角和目录尺寸；顺坡组件始终贴所属屋面，任意角旋转不改变物理边长。
2. 已锁组件与锁区空白不可被占用；越界、重叠、设备避让冲突由后端拒绝，并保留原方案。
3. 锁定、拖拽、旋转、详细复算、保存和撤销属于同一版本链；取消预览不写盘，旧预览不能在版本变化后提交。
4. 详细比较显示真实遮挡、发电、电气及经济变化；缺天气或计算失败显示未完成。新位置不沿用旧版热力或组串。
5. 保存重开与撤销后核对真实角点；真实WebGL操作和公共HTTP契约均有验证。

演示路径：`manual-modules-demo` v3 → 选未锁组件 → 移近南侧设备 → 预览看到S01失败 → 保存 → 旋转比较 → 撤销。已有合成演示在v4平均遮挡4.8274%，v5旋转后4.4772%，v6恢复v4；这是具体样例的计算值，不是泛化改进率。

赛事对应：OPC工具操作录屏和工作流演示；蜂鸟产品服务能力说明。

### P1：规则问题定位与修复预览

在规则页展示失败证据和“定位”“进入局部修改”按钮。首批只定位有明确对象证据的四类：

| 规则 | 对象来源 | 可操作范围 |
| --- | --- | --- |
| S01单板遮挡超阈值 | 同版本 `shading.modules` 的真实损失与规则限值 | 高亮超阈值组件；提供仅移除未锁定超阈值组件的预览 |
| E08未接入组串 | 同版本 `electrical.unused_modules` | 高亮未接线组件，进入局部编辑；不自动删除 |
| E10直流线路失败 | 同版本 `electrical.cables.dc` 中明确 `feasible=false` 的线路，通过真实string ID关联成员 | 定位对应组件和组串；保留压降、载流或不可达的原证据，不杜撰故障点 |
| L01坡面荷载失败 | 同版本结构结果的失败坡面及设计中实际成员 | 定位该坡面和所属组件，保留结构复核提示；不把整面结论解释成某个确定失效锚点 |

验收条件：

1. 当前版缺分析、显式分析版本不符、对象编号不在设计中、证据不完整时，说明无法定位的原因，不用其他版本补齐。
2. “定位”只改变高亮和视角，不修改方案，也不自动改动局部编辑的选择；“进入局部修改”再明确选中可编辑对象。
3. S01修复列出将移除的明确ID和保留的锁定ID，默认详细复算，只生成预览；不能直接保存，也不保证所有规则通过。
4. 若所有超阈值组件都锁定，禁止该修复并解释原因；若未锁组件删除后仍有容量、电气或遮挡失败，照实显示。
5. 历史只读版本可查看本版证据，不能进入修改或修复；实时切换版本后旧诊断事件无效。
6. 其它规则保留原始数值、限值、依据及建议，并明确首批尚无对象定位，不画猜测位置。

首批实现契约：`design_diagnostics.build(project, design, rules, shading, electrical, structure, locked_ids, source_versions=...)`返回本版本诊断。`rules.json`与`structure.json`目前缺少顶层version，调用方必须提供从确切 `analysis/vN` 路径读取的版本来源；任何显式版本冲突优先拒绝。归档先通过原有摘要校验再传入，不能为了定位绕过归档完整性检查。

演示路径：`manual-modules-demo` v6 → 规则 → S01 → 定位设备北侧超阈值板 → 预览移除未锁板 → 对比装机/发电/规则 → 取消或确认。另用锁定超阈值组件的独立测试证明保护语义，不改写现有演示版本。

赛事对应：将智能体工程反馈解释到具体对象，使评委能核对“为什么改、改哪里、代价是什么”。这是产品价值判断，不是官方量化评分项。

### P1：真实交付证据与耗时成本摘要

在方案结果中显示这次运行和交付的可核验摘要，复用已有文件与原生账本，不依赖新模型调用。将“工程投资估算”“本次软件运行费用”和“尚未采集的人工服务成本”分开。

验收条件：

1. 显示项目/设计版本、输入与工程假设、是否复算完成、规则结果、审核状态和本版交付文件摘要；所有指标回到同一版本来源。
2. 只从现有原生账本汇总模型请求、Token、设计/审核时间和估算费用；按费用编号去重，不把缺失计费记为0，不将估算标为实付。
3. 离线手动演示明确没有新的模型运行；计算用时与会话总用时分开，未知记录显示未提供。
4. 人工整理/复核时长、失败重做成本若没有采集，就保留未知。不得仅用Token费用宣称完整交付单价，也不得自动生成订单、客户、收入或付费证明。
5. 旧版摘要保持只读；缺模型账本、缺审核、缺导出时显示具体缺项，不能显示“交付完成”。

演示路径：查看手动示例的工程摘要与未发生的模型运行；再打开仓库已公开、可校验的AGH案例查看真实运行与审核记录。两者分别呈现，不能拼接成同一次新实验。

赛事对应：OPC要求低成本部署与工作流证明；蜂鸟申报要求产品服务和运营可行性。实际费用摘要能支撑经营测算，但不证明市场愿意付费。
