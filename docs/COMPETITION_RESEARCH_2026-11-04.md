# 三项赛事官方要求与参赛证据研究

核对日期：2026-11-04。本文依据赛事官方平台、江苏省住房城乡建设厅原始通知，以及用户提供的两份泰州盖章通知。它研究报名规则和备赛证据，不对当前代码或产品完成度作审计。下文的赛道匹配与改进优先级是研究判断，不是官方评分权重，也不是获奖概率预测。

## 结论与适配方向

光筑所述的屋顶光伏方案设计、工程复算和智能体工作流，与三赛均有可解释的参赛联系。其中，江苏住建赛的“产业发展”分赛道对专业主题的匹配最直接；OPC 赛更需要证明个人或小团队能低成本完成本地业务；蜂鸟赛更需要证明项目能在泰州形成可经营的产品或服务。方向匹配不等于已通过资格审查，也不等于具有获奖把握。资格仍取决于实际参赛人的身份、年龄、学校或在泰关系和材料真实性。

不能从现有官方材料得出“一等奖 91% / 93% / 94%”“任意奖 96%–98%”。这类数值没有可追溯的样本、比较群体和校准过程。尤其蜂鸟通知采用名次补助口径，OPC 的复赛人数与奖项总人数尚有歧义，三个比赛不能套用同一获奖分类。

## 最能提升参赛竞争力的证据工作

以下是依据官方材料作出的备赛建议，不代表官方要求固定样本数量、固定评测通过率或固定权重。

1. **先形成能复现的一条真实交付链。** 选定一个经授权、来源清楚的屋顶或园区需求，展示输入条件、AI 调用工程工具、结果检查、人工复核、导出交付。保存同一版本的输入、运行记录、失败与修复、成本和成果。合成案例可以辅助演示，但应与真实项目分开标明。江苏赛需要验证数据，OPC 需要原型和工作流，蜂鸟需要能交付的服务，三者都可复用这份证据。
2. **做可公平比较的成效验证。** 明确基线、相同输入和质量要求，记录总耗时、人工干预、失败重做、计算与 API 成本，报告所有任务及失败例，不只展示最好的案例。工程精度应由独立结果或具备对应专业能力的人复核。若没有这些数据，只能说明原型能力和待验证假设，不能宣称已经节省某个百分比或可以替代专业审核。
3. **把 AI 的贡献说清并证明。** 展示哪些步骤由模型理解、调用和规划，哪些步骤由确定性工程计算完成，哪些必须由人确认。用任务记录说明 AI 带来的价值和边界，避免仅以聊天界面或功能数量论证创新性。可做固定工作流与智能体流程的对照，但不要把内部功能测试等同于真实模型成功率。
4. **按三赛分别整理材料。** 江苏材料重点写技术差异、验证结果和行业推广；OPC 材料重点写本地业务、小团队交付和部署复现；蜂鸟材料重点写客户、价格假设、交付周期、毛利测算条件和在泰经营计划。未获得客户或收入时，应给出明确的试用/访谈计划并标注尚未验证，不得补造合同、订单、付费或合作证明。
5. **准备失败可解释的现场演示。** 演示一次需求变更、一次规则不通过、一次人工确认后修复或回退，确保能说明每项变化的来源。OPC 按官方 8 分钟+3 分钟安排练习；江苏与蜂鸟的具体路演分钟数尚未从本次官方材料核实，不能直接照搬。录屏可备份真实演示，但不要把预录画面表述成当场运行。

建议优先顺序为：消除会使核心结果或版本链失真的缺陷 → 做独立复核和公平对照 → 获取真实需求或试用证据 → 完成三份不同叙事的报名包 → 稳定演示。此顺序是产品与备赛判断，当前产品究竟存在哪些缺陷需另行审计；本文不把任何建议写成已实现。

## 为什么暂时不能给出可信获奖百分比

目前缺少的数据包括：

- 各赛道或组别最终有效报名数量、项目质量分布以及主要竞争项目的可比资料。
- 江苏各等级确切名额；OPC 复赛人数与奖项名额的正式解释；蜂鸟约 10 个决赛项目的最终口径。
- 各赛完整评分量表、权重、晋级办法、分数分布及同分处理规则。
- 光筑当前提交版本的独立复核、真实模型运行表现、真实场景结果、客户证据以及正式路演表现。
- 可用于校准的历史可比项目数据，以及预测在留出样本上的误差。往届、别的城市或别的 OPC 比赛的数据不能直接充当本届分母。

因此，既不能把单个项目自评分当作获奖概率，也不能用软件测试通过率或演示成功率代替评委选中概率。即使得到了名额和总人数，名额/人数也只是群体席位比例，不是这个项目的获奖概率。三赛结果受相同产品、材料和团队因素影响，不能未经依据假设相互独立后合成“至少一赛获奖”概率。

当前可诚实给出的判断是：三赛方向都具备报名研究价值；专业主题与江苏产业发展分赛道的关联最直接；OPC 对部署成本和本地重复业务证据更敏感；蜂鸟的经营与落地证据不能用工程功能替代。这些是匹配判断，尚不足以给出有校准意义的胜率区间或一等奖排序。
